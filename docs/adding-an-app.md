# Adding an application

The next major version (**v5**) is defined as "a fifth application": the rule
is that `MAJOR` only increases when an app is added. This is the whole procedure.

## 1. The class

Derive from `ESP_Brookesia_PhoneApp`, one `.hpp` and one `.cpp` in `main/`:

```cpp
// app_clock.hpp
#pragma once
#include "esp_brookesia.hpp"

class AppClock : public ESP_Brookesia_PhoneApp {
public:
    AppClock();
    bool run(void) override;    // build the UI
    bool back(void) override;   // destroy it, then notifyCoreClosed()

private:
    lv_obj_t *_root = nullptr;
    static void on_event(lv_event_t *e);   // must be public-accessible
};
```

```cpp
// app_clock.cpp
#include "app_clock.hpp"
#include "icons/app_icons.h"

AppClock::AppClock() :
    ESP_Brookesia_PhoneApp("Horloge", &app_icon_clock, true, true, true) {}

bool AppClock::run(void)
{
    const lv_area_t &va = getVisualArea();          // (0,50)-(409,501)
    int usable_h = lv_area_get_height(&va) - va.y1; // 402: the content budget
    int screen_h = (int)lv_obj_get_height(lv_scr_act()); // 452: the container

    _root = lv_obj_create(lv_scr_act());
    lv_obj_set_pos(_root, 0, 0);
    lv_obj_set_size(_root, LV_PCT(100), screen_h);  // covers the whole screen
    lv_obj_set_style_bg_color(_root, lv_color_hex(0x0E0E10), 0);
    lv_obj_set_style_border_width(_root, 0, 0);
    lv_obj_set_style_radius(_root, 0, 0);
    lv_obj_set_style_pad_all(_root, 12, 0);

    /* ... content laid out for usable_h, not for screen_h ... */
    return true;
}

bool AppClock::back(void)
{
    notifyCoreClosed();
    return true;
}
```

Three things matter here and each of them has cost time before:

- **the container is 452 px tall, the content budget is 402** — see
  [pitfall 17](pitfalls.md#17-an-app-screen-is-452-px-tall-not-402). Sizing the
  container to 402 leaves a 50 px strip painted by the screen background.
- **the screen background must be opaque** (`COL_BG`), otherwise whatever was
  on screen shows through.
- **no `-O2`**, and no blocking work in `run()`: I2C or audio initialisation on
  the LVGL task deadlocks the interface
  ([pitfall 7](pitfalls.md#7-the-ui-freezes-when-an-app-opens)).

## 2. The icon

150 × 150 exactly, ARGB8888, one hue per app. Two ways:

```powershell
# a) parametric drawing: add an entry to the ICONS list in tools/make_icons.py
python tools\make_icons.py

# b) convert a square PNG with a transparent background
python tools\png2lvgl.py mon-icone.png app_icon_clock
```

Both write `main/icons/app_icon_clock.c` and regenerate `main/icons/app_icons.h`.
Never hand-write those arrays: the word order is `0xAARRGGBB`
([pitfall 13](pitfalls.md#13-colours-inverted-inside-an-icon)).

## 3. Registration

`main/CMakeLists.txt` — sources are listed explicitly, there is no glob:

```cmake
idf_component_register(
    SRCS "main.cpp" "app_settings.cpp" "app_assistant.cpp" "app_music.cpp"
         "app_clock.cpp"
         "xiaozhi_client.cpp"
         "icons/app_icon_settings.c" "icons/app_icon_assistant.c"
         "icons/app_icon_music.c" "icons/app_icon_clock.c"
    INCLUDE_DIRS "."
)
```

`main/main.cpp` — after the existing apps, because install order **is** page
order:

```cpp
AppClock *clock = new AppClock();
ESP_BROOKESIA_CHECK_NULL_EXIT(clock, "Creation de l'app Horloge impossible");
ESP_BROOKESIA_CHECK_FALSE_EXIT(
    (s_phone->installApp(clock) >= 0), "Installation de l'app Horloge echouee");
```

Nothing else. The launcher allocates the next page on its own and logs
`All table pages are full, create a new page` one more time.

## 4. Verify on the board

Boot log must show the new page count and no error:

```
MONTRE: === montre : interface prete ===
Brookesia: (addIcon): All table pages are full, create a new page   x3 with 4 apps
```

Then open it — with a finger, not a script:

1. swipe to page 4, tap the icon;
2. the app must paint its whole 452 px, with no strip at the bottom and no
   leftovers at the top;
3. if it has a back path, return to the launcher and check that the page is
   intact.

The autotest harness can open a page for you
([diagnostics.md](diagnostics.md)), but remember: it sends a synthetic click and
therefore **never exercises the press-zoom path** that a finger does. A test
that passes is not a proof that the UI behaves.

## 5. Checklist before committing

- [ ] icon exactly 150 × 150, generated by a tool, listed in `CMakeLists.txt`
- [ ] container sized from `lv_scr_act()` height, content sized for 402 px
- [ ] opaque screen background
- [ ] no blocking I2C/audio call in `run()`
- [ ] `back()` idempotent, called through `lv_async_call` from a callback
- [ ] no `-O2`, no `target_compile_definitions` left behind
- [ ] `idf.py size` shows the expected growth (~90 KB per icon)
- [ ] tested on the watch with a finger
- [ ] `CHANGELOG.md`, `VERSION`, tag — see [versioning.md](versioning.md)
